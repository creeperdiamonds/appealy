プライバシー

最終更新: 2026年8月18日

このページは appealy.app のホスティング版について説明します。セルフホストの場合、ここに書かれた 内容は一切当てはまりません。あなたのインスタンスは Discord と、あなた自身のデータベースとだけ やり取りし、データを保持しているのはそのインスタンスの運営者です。

このページは英語版 Privacy の参考訳です。 解釈に相違が生じた場合は、英語版が優先します。

保存されるもの

Appealy は Discord サーバーの応募、異議申し立て、チケットを扱うボットです。保存するもののほとんどは、 Discord の識別子か、フォームに誰かが入力した内容のどちらかです。

データベースに書き込まれる内容と、その理由。
データ 理由
Discord ID ユーザー、サーバー、チャンネル、ロール、メッセージの ID。ボットの動作はすべてこれらで指定されます。
サーバー名とアイコンのハッシュ ダッシュボードでどのサーバーを見ているかを表示するため。
応募と回答 応募者が書いた内容、対象のフォーム、結果、審査担当者、却下理由がある場合はその理由。
BAN 異議申し立て 応募と同じ構造です。サーバーで異議申し立てが有効なときに、誰かが BAN されると作成されます。
チケット 誰が開いたか、誰が担当したか、いつ閉じたか、評価機能が有効なら評価、書き起こしが有効ならそのリンク。
ギブアウェイの参加、投票 どのユーザーが参加・投票したか。同じ人が二重に参加できないようにするため。
サーバー設定 フォーム、質問、パネル、DM テンプレート、チケットの種類、認証、ウェルカム、ロールメニュー、荒らし対策、定型応答、固定メッセージ、スタッフ権限の委任。
セッション appealy_session クッキーから参照されるセッションの行。
Discord OAuth トークン サインイン時に Discord が発行するアクセストークンとリフレッシュトークン。ダッシュボードが管理対象サーバーを一覧表示するために使います。保存時に暗号化されます。
請求状態 サーバーがどのプランかと、決済事業者側のサブスクリプション参照 ID。カード情報は一切保存しません — 下記を参照してください。

収集しないもの

  • テレメトリはありません。これは文章での約束ではなく shared/config/deployment.ts の定数として表明されているので、変われば差分に現れます。
  • メッセージの保存はしません。ボットは Message Content インテントを、固定メッセージを 再投稿すべきほどチャンネルが動いたかを判断するためだけに使います。メッセージ本文をデータベースに 書き込むことはありません。チャンネルの履歴を読む唯一の機能はチケットの書き起こしで、これはチケットを 閉じたときに生成され、設定したチャンネル — 当方ではなくあなたのサーバー — にプレーンテキスト ファイルとして投稿されます。保存されるのはその URL だけで、書き起こしを有効にした場合にのみ作成されます。
  • カード情報は扱いません。本サービスに届くことはありません。販売事業者が merchant of record として、自社のページで決済を受け取ります。
  • このウェブサイトに解析ツールはありません。いま読んでいるページには JavaScript が 一切含まれていません。このドメインの外へ要求するのは、2 種類の書体（Google Fonts）だけです。
  • 稼働状況ページでサーバー ID の問い合わせは発生しません。シャードの計算は単なる算術なので、 ブラウザ内で完結します。何も送信されない以上、記録も、キャッシュも、漏洩も起こりようがありません。

クッキー

1 つだけです: appealy_session。httpOnly（JavaScript から読めません）、 SameSite=Lax、本番環境では Secure が付きます。保持するのはセッション識別子 のみで、それ以外は何もありません — トークンもユーザーデータも含みません。サインアウトすると削除されます。

解析用クッキーもサードパーティークッキーもありません。ダッシュボードを API と同じオリジンから配信して いるのは、まさにこのためです。設定を緩めてブラウザにサードパーティー扱いさせるのではなく、構造として セッションクッキーをファーストパーティーに保っています。

保存期間

サーバーごとに履歴の保存期間があり、これも計測対象の上限の 1 つです。無料プランで 30 日、最大で 5 年です。 審査済みの応募 — 承認、却下、取り下げ — は期間を過ぎると削除対象になり、回答も所属する応募と ともに削除されます。

自動削除はまだ有効になっていません。このページでそれを偽るつもりはありません。 保存期間は参照されるすべての箇所で適用されており、期限切れの応募を削除するジョブも実装済みで動いています — ただし現在は報告モードで、削除する代わりに「削除するはずだったもの」を記録しています。 そのため、期間を過ぎた審査済みの応募は今も保存されています。

これは見落としではありません。この削除処理は一度も実行されていないため、初回の実行では、 実行されてこなかったがゆえに溜まった期限切れの応募すべてを、全サーバーにわたって一度に、 取り消せない形で削除することになります。それは数字を見たうえで下すべき判断であって、既定で有効にしておいて あとから気づくようなものではありません。有効にした際にはこの段落を削除し、上の一文だけが残ります。

それより前にサーバーの履歴を消したい場合は、/export で控えを取ったうえで、下記の宛先に 削除を依頼してください。手作業で対応します。

審査待ちの応募は、どのプランでも削除されません。それは審査待ち行列にある進行中の案件であり、 期限切れを理由に消せば、まだ結果を待っている人の応募を黙って捨てることになるからです。

サーバーからボットを外しても、そのサーバーの設定は削除されません。再度招待したときに、作り直すのではなく 元の状態に戻せるようにするためです。休止ではなく完全に消したい場合は、エクスポートしてから削除を依頼してください。

誰が何を見られるか

  • 応募者は、ボットから届く DM を通じて自分の応募を見られます。
  • 審査担当者は、アクセスを与えられたフォームの応募を見られます。アクセス権は Discord の管理者権限を与えることなく、個人単位で委任できます。
  • 審査チャンネルを見られる人は、審査用の埋め込みに表示される内容をすべて見られます。 フォームごとに、埋め込みから回答を完全に省く設定ができます — 審査担当者は Discord 上では応募の 統計だけを見て、回答はダッシュボードで読む形になります。個人的なことを尋ねるフォームでは有効にする価値が あります。Discord のチャンネルはメッセージ履歴を無期限に保持するからです。
  • サーバー所有者のみが、完全なデータエクスポートと一括インポートを実行できます。これは 本製品の他のどの権限よりも意図的に厳しくしています。応募者が書いた内容すべての完全な写しを、日常の管理を 任せた管理者が引き出せないという保証を求める所有者がいるためです。

データの持ち出し

サーバー内で /export を実行すると、そのサーバーのフォーム、質問、パネル、応募、回答、 DM テンプレート、チケット、ギブアウェイ、認証とウェルカムの設定、ロールメニュー、荒らし対策の設定、 定型応答、固定メッセージ、スタッフ権限の委任をすべて含む JSON ファイルが 1 つ生成されます。請求情報と セッション情報は意図的に除外しています — それらはアカウントに属するもので、持ち運べるサーバー設定 ではありません。

目的は、共有ボットでは手狭になったサーバーが、自前のセルフホストインスタンスへ移り、すべてを持って いけるようにすることです。囲い込みの手続きも、エクスポート料金もありません。

関わる第三者

ホスティング版に関わる第三者。
相手 渡るもの
Discord ボットが送受信するすべて。本サービスが動作している基盤です。
Paddle 有料プランの販売事業者（merchant of record）。決済を処理し、販売先での売上税・VAT の登録を担います。カード情報は当方ではなく Paddle に渡ります。
Google Cloud ホスティング版の稼働場所: Cloud Run、Cloud SQL、Memorystore、Secret Manager。

データを販売することはなく、この表にない相手と共有することもありません。

削除の依頼

サーバー所有者は、すべてをエクスポートしたうえで、そのサーバーのデータの削除を依頼できます。個々の応募者は、 まず応募先サーバーのスタッフに相談してください — 応募を保持しているのはそのサーバーであり、スタッフが 直接対応できます。

contact@creeperdiamonds.xyz までメールしてください。 公開の Issue ではなくメールをお使いください。削除の依頼では、対象となるサーバー名や、場合によっては個人名を 挙げる必要があり、Issue トラッカーではそれがリポジトリを読めるすべての人に公開されてしまいます。 不具合の報告先としては GitHub リポジトリが引き続き適切です。

セルフホストの場合

セルフホストのインスタンスは、当方へ何も送信しません — テレメトリも、ライセンス確認も、外部への 通信もありません。そのインスタンスのデータベースにあるデータに責任を負うのは運営者であり、このページは その内容を一切説明するものではありません。
